# Подключение к Figma — бесплатно

Три канала, все работают на бесплатном тарифе Figma. Между собой не конфликтуют,
можно пользоваться любым.

| Канал | Что даёт | Цена | Ограничение |
|---|---|---|---|
| Локальный плагин `tools/figma-plugin` | читает выделение в JSON и собирает JSON обратно во Figma (и запись, и чтение) | 0 ₽, публиковать не нужно | работает внутри файла, вручную через окно плагина |
| REST API + `tools/figma.mjs` | список фреймов, размеры, выгрузка макетов в PNG/SVG | 0 ₽, нужен токен | только чтение: рисовать через API нельзя |
| Figma MCP-сервер | то же, что REST, но инструментами для ИИ | 0 ₽ (community) / платный Dev-режим у официального | официальный требует платного места, community — тот же токен |

Ниже — установка по шагам.

---

## 1. Плагин (двусторонний мост)

Нужен Figma **для Windows** (десктопное приложение: `figma.com/downloads`).
В браузере разработческие плагины тоже открываются, но через десктоп удобнее.

1. Открыть любой файл Figma → меню **Plugins → Development → Import plugin from manifest…**
2. Выбрать файл `tools/figma-plugin/manifest.json` из папки проекта.
3. Плагин появится в том же меню: **Plugins → Development → NE-KLUY bridge**.
4. Готово. Публикация в Community не нужна, аккаунт остаётся бесплатным.

**Экспорт (Figma → ассистент).** Выделить фрейм или слой → запустить плагин →
кнопка «Экспорт выделения» → «Скопировать». В JSON попадут: дерево слоёв, координаты,
размеры, скругления, заливки в HEX, обводки, шрифт/кегль/межстрочный для текста,
авто-раскладка и отступы для фреймов. Этот JSON можно вставить в чат.

**Импорт (ассистент → Figma).** Вставить JSON в поле плагина → «Собрать во Figma».
Плагин создаст фреймы, тексты и прямоугольники на текущей странице и сфокусируется на них.
Шрифты грузятся с фолбэком на Inter: если в макете был недоступный шрифт, текст всё равно появится.

Формат узла (может пригодиться, если писать JSON руками):

```json
{
  "nodes": [
    {
      "name": "Экран вызова",
      "type": "FRAME",
      "x": 0, "y": 0, "width": 390, "height": 844,
      "fill": "#0B1220", "radius": 44,
      "layout": "VERTICAL", "gap": 16, "padding": [24, 24, 24, 24],
      "children": [
        { "type": "TEXT", "name": "Имя", "x": 24, "y": 120, "width": 342, "height": 40,
          "text": "Неизвестный", "fontSize": 28, "align": "CENTER", "color": "#FFFFFF" }
      ]
    }
  ]
}
```

`x`/`y` детей — абсолютные: плагин сам переводит их во внутренние координаты родителя.

## 2. REST API (чтение макетов картинками)

1. Figma → аватар → **Settings → Security → Personal access tokens → Generate new token**.
2. Обязательные права: `file_content:read` (для выгрузки картинок этого хватает).
3. Токен не вставлять в код и в чат. Варианты хранения:
   - переменная окружения `FIGMA_TOKEN`;
   - файл `tools/.figma-token` (одна строка) — он уже в `.gitignore`.

`fileKey` — кусок адреса файла: `figma.com/design/<fileKey>/<имя>?node-id=12-345`.
`node-id` в адресе пишется через дефис, в API — через двоеточие (`12:345`).

```bash
# что внутри файла: страницы, фреймы, размеры, id
node tools/figma.mjs info <fileKey>

# выгрузить фреймы картинками (по умолчанию PNG ×2)
node tools/figma.mjs render <fileKey> 12:345,12:346 --format png --scale 2

# вектор для вёрстки
node tools/figma.mjs render <fileKey> 12:345 --format svg
```

Картинки складываются в `tools/figma-out/`. Дальше их можно положить в `src/assets/`
и подключить в сборку как обычный импорт — esbuild подхватит (`".png": "file"` уже настроен).

Частота запросов у бесплатного тарифа ограничена; для десятка макетов это не мешает.

## 3. MCP-сервер (если нужны инструменты вместо ручных команд)

MCP — протокол, которым ассистент вызывает внешние инструменты. Для Figma есть:

- **официальный** `Figma Dev Mode MCP` — входит в платный Dev-режим, на бесплатном тарифе недоступен;
- **community** (`figma-developer-mcp` и подобные) — работают на том же REST-токене,
  то есть те же права «только чтение», что в разделе 2.

Вывод: на бесплатном тарифе реальная двусторонняя работа идёт через плагин, а REST/MCP —
удобный способ забрать готовые макеты картинками. Писать в файл Figma через API нельзя
принципиально: запись доступна только плагину.

## План действий: включаем один раз, дальше работаем

Порядок такой. Шаги 1–3 делаются один раз, шаги 4–5 — это уже рабочий цикл.

### Шаг 1. Поставить Figma для Windows (один раз, ~2 минуты)
`figma.com/downloads` → установить → войти в свой аккаунт. Бесплатного хватает:
личных файлов сколько угодно, ограничения платного тарифа касаются командной работы.

### Шаг 2. Выпустить токен (один раз, ~1 минуту)
Figma → аватар → **Settings → Security → Personal access tokens → Generate new token**,
права `file_content:read`. Положить строку в файл
`tools/.figma-token` (одна строка, без кавычек). Файл в `.gitignore`.
В чат токен присылать не нужно — я читаю его из файла.

### Шаг 3. Импортировать плагин (один раз, ~1 минуту)
Figma → **Plugins → Development → Import plugin from manifest…** →
`tools/figma-plugin/manifest.json`. В меню появится **NE-KLUY bridge**.

### Шаг 4. Дальше задача ставится одной строкой
Примеры формулировок, которые я смогу выполнять без уточнений:

- «возьми макет по ссылке `figma.com/design/<ключ>/…?node-id=12-345`, сделай по нему секцию»;
- «выгрузи все фреймы из файла и покажи, что в них»;
- «сверь, что на сайте размеры и цвета как в макете»;
- «собери этот блок во Figma, чтобы я посмотрел».

Что я делаю сам:

| Действие | Чем |
|---|---|
| прочитать файл: страницы, фреймы, размеры, id | `node tools/figma.mjs info <fileKey>` |
| выгрузить макет картинкой или вектором | `node tools/figma.mjs render <fileKey> <ids> --format png\|svg --scale 2` |
| вытащить точные цвета, отступы, кегли | разбор JSON-дерева по REST |
| положить макет в сайт | `src/assets/` — esbuild подхватит импорт |

### Шаг 5. Обратное направление: макет от меня во Figma
Записать в файл Figma через API нельзя — это ограничение самой Figma, не моё.
Два рабочих пути без платной подписки:

1. **Плагин.** Я отдаю JSON (или файл `tools/figma-out/mockup.json`) → вы открываете
   плагин → вставляете JSON → **Собрать во Figma**. Появятся фреймы, тексты и
   прямоугольники с нужными размерами, скруглениями и цветами.
2. **SVG.** Я собираю макет в SVG → вы перетаскиваете файл в Figma, он встаёт вектором.

## Что проверено, а что нет

- `manifest.json` — валидный JSON; `code.js` и скрипт интерфейса проходят проверку синтаксиса.
- `tools/figma.mjs` — проверен запуск без токена: выдаёт понятную инструкцию.
- REST отвечает `401` без токена, значит сервис доступен.
- Вживую в Figma **не запускалось**: приложения Figma на этой машине нет, токена тоже нет.
  Первый запуск — за вами; если плагин ругнётся, пришлите текст ошибки, поправлю.

## Состояние на 2026-11-19: токен подключён

- Токен лежит в `tools/.figma-token` (600, в `.gitignore`).
- Проверка авторизации: `GET /v1/files/ABC` с заголовком `X-Figma-Token` → `404 Not found`
  (то есть токен принят, файла с таким ключом нет). Без токена было бы `401`.
- **Важно про заголовок:** персональные токены `figd_…` Figma принимает только в
  `X-Figma-Token`. `Authorization: Bearer` даёт `401 figd_ tokens must be passed via
  X-Figma-Token header`. В `tools/figma.mjs` это уже учтено: `figd_` → `X-Figma-Token`,
  OAuth (`eyJ…`) → `Bearer`.
- У токена scope `file_content:read`: он читает конкретный файл по ключу, но **не умеет
  перечислять файлы** (`/v1/me` отвечает `403 Invalid scope`). Поэтому для работы нужен
  fileKey — он берётся из ссылки: `figma.com/design/<fileKey>/<имя>?node-id=12-345`.
  Если хочешь, чтобы я сам находил файлы, при генерации токена добавь scope `files:read`.
